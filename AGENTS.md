# AGENTS.md

**Juniper Front Desk** is a self-serve voice agent demo: a vet clinic front desk you call from the
browser. It runs on the Deepgram Voice Agent API with Flux listening (`flux-general-en`, v2), Flux
TTS speaking (`flux-*-en`, v2) and a Deepgram-hosted LLM (`anthropic` / `claude-haiku-4-5`), so
there is no LLM key. The clinic and its prompt are ported from the Tech Week talk demo,
[hold-please](https://github.com/samgutentag-deepgram/hold-please).

## Stack, resolved 2026-10-23

React 19.3 + Vite 8, TypeScript 7, `@deepgram/react` 0.2.0, `@deepgram/ui` 0.1.6,
`@deepgram/agents` 0.2.0, Radix Switch and ToggleGroup, Express 5.3 (static only), Vitest 5,
pnpm 12, Node 22. `pnpm-workspace.yaml` overrides `@deepgram/react` and `@deepgram/agents` to
0.2.0, because `@deepgram/ui` 0.1.6 still pins 0.1.x and two copies means two React contexts.

## Commands

| Command | Does |
|---|---|
| `pnpm dev` | Vite on <http://localhost:8080>. All you need locally; there is no API |
| `pnpm check` | Typecheck everything, including `server.js` and `scripts/` |
| `pnpm test` | Unit tests, plus the style-pack check |
| `pnpm build` then `pnpm start` | The production build, served by `server.js` on 8081 (8080 on Fly) |

Run `pnpm check` and `pnpm test` before committing.

## Auth: the visitor's key, never ours

There is no server key. The visitor pastes their own, and `@deepgram/agents` sends it from the
browser straight to Deepgram as a websocket subprotocol. `server.js` only serves the built page and
never sees the key. A server route that traded the key for a short-lived token was tried and
dropped: `/v1/auth/grant` returns 403 for keys without a high enough role, which many visitor keys
are. Never log the key, put it in a URL, or persist it: it lives in React state and a reload drops
it.

## Where things are

| File | Holds |
|---|---|
| `src/lib/agent-config.ts` | Every session setting. The file a reader forks |
| `src/lib/clinic.ts` | The clinic, the prompt, keyterms, booking reference |
| `src/lib/toggles.ts` | The three switches, their before and after, and the code each changes |
| `src/lib/script.ts` | The lines both modes share, with a reply per switch position |
| `src/lib/guide.ts` | The walkthrough: chapters, the A/B state machine, the call so far for a jump |
| `src/lib/captions.ts` | The live tab's second, listen-only Flux stream for word-by-word captions |
| `src/lib/cta.ts` | The credit call to action, its copy, and the UTM tags on signup links |
| `src/lib/demo-manifest.json` | Generated by `scripts/render-demo.ts`. Never edit by hand |
| `src/styles/packs/` | The only place literal colors and fonts live |
| `server.js` | Static serving, nothing else |
| `scripts/smoke.ts` | Live end-to-end check with a synthesized caller, no mic |
| `scripts/render-demo.ts` | Rebuilds the replay audio and transcripts |

## Rules

Literal colors, fonts, and radii live only in `src/styles/packs/`. Everywhere else uses
`var(--dg-*)`. `pnpm test` enforces this. The active pack is `flux-2026-light`; the dark
`flux-2026` sits beside it, and `src/styles/theme.css` imports exactly one of them, so a rebrand is
that one line.

Flux TTS `expressivity` is fixed for a session, so changing tone restarts the call. Voice changes
live with `UpdateSpeak`; keyterms and end of turn with one `UpdateListen` that always carries every
switch. Barge-in off is done client side by muting the mic while the agent talks, because the Voice
Agent API always listens.

A live call only takes earlier conversation at connect, so jumping to a chapter reconnects with
`historyBefore()` as context and no greeting.

Change a line in `src/lib/script.ts` and the replay is stale: rerun `scripts/render-demo.ts`.

The Fly app is `dg-devrel-juniper-front-desk`, in the `deepgram` org.
